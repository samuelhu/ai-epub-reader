PROJECT OVERVIEW
────────────────
A Chrome MV3 extension built with @crxjs/vite-plugin, React 19, TypeScript 6,
Vite 8. Reads EPUB (.epub) and plain text (.txt) files with an AI Tutor that
explains selected passages using multiple provider backends (OpenAI, DeepSeek,
Anthropic Claude, Google Gemini, Ollama local). Features streaming responses,
text-to-speech, typography controls, and fullscreen reading.

Key dependencies: epubjs 0.3.93 (EPUB rendering), Dexie 4.4.2 (IndexedDB),
lucide-react 1.16.0 (icons).

ENTRY POINTS
────────────────
- index.html — SPA shell, loads Google Fonts (Inter, Literata, JetBrains Mono)
- src/main.tsx — React 19 createRoot entry
- src/App.tsx — Top-level router (library / reader / settings views)
- src/background.ts — Service worker (3 lines: opens extension on action click)
- manifest.json — MV3 manifest with host_permissions for all 5 AI providers

ARCHITECTURE NOTES
──────────────────

1. Dual rendering path:
   - EPUB: epubjs Book → Rendition in iframe, paginated continuous flow
   - TXT: plain <div> with paragraphs split on /\n{2,}/, scroll-based progress

2. Data layer:
   - Dexie IndexedDB with V2 schema migration (blobs separated into `files` table)
   - Book interface: id, title, author, cover (Blob), progress (string),
     progressPercent (number), addedAt, lastOpenedAt, fileType ('epub'|'txt')
   - BookFile interface: bookId, fileData (Blob)
   - bookCache.ts: LRU cache (max 8) for epubjs Book objects with content
     fingerprinting to detect file changes

3. AI provider architecture (src/utils/ai.ts):
   - explainText(text, type, onChunk?, signal?) — single entry point
   - Provider routing: openai, deepseek, anthropic, gemini, ollama
   - Streaming: SSE for cloud providers (\n\n delimiter), JSONL for Ollama (\n)
   - rAF throttling prevents render storms from per-character streaming
   - AbortController propagated through entire chain for cancellation
   - Language detection: auto (from navigator.language) or 11 manual overrides
   - System prompts: Brief (1-2 sentences) vs Detailed (markdown sections)
   - Default provider: deepseek (deepseek-v4-flash model)

4. State management:
   - Reader preferences: localStorage (synchronous reads for initial state)
   - AI settings: chrome.storage.local (extension-native, async)
   - Migration: migrateFromLocalStorage() copies legacy localStorage to chrome.storage

5. Typography system:
   - Defaults: Literata font, 1.7 line height, 40px margins, 720px max-width
   - EPUB: epubjs themes.register() + content hook injects CSS into iframe
   - TXT: direct inline style application on container div
   - Theme colors centralized in src/utils/theme.ts (light/dark/sepia)
   - Live line-height/margin updates via direct iframe body style manipulation
     (avoids epubjs round-trip for smoother sliders)

6. AI panel positioning:
   - EPUB: calculates from selection bounding rect relative to iframe
   - TXT: calculates from selection bounding rect in main document
   - Falls back to CSS default (right: 1.5rem, top: 4.5rem) if calculation fails
   - Pin mode locks position; resize handler re-clamps within viewport
   - Auto-trigger: Brief explanation fires on text selection (debounced by ref)

KNOWN BEHAVIORS & TRADE-OFFS
─────────────────────────────

1. Ollama requires OLLAMA_ORIGINS="*" ollama serve
   → Extension's chrome-extension:// origin is rejected by default CORS
   → Service worker proxy was tested but didn't work for the user
   → Current approach: direct fetch with server-side origin allow-all
   → Hint displayed in Settings when Ollama provider is selected

2. TXT progress restore on reopen
   → Uses txtInitialProgressRef to pass progress from loadBook to restore effect
   → This works because React 18 batches setFileType + setTxtContent updates
   → Ref is set before state updates during the async loadBook function

3. AI streaming uses requestAnimationFrame throttling
   → Prevents React render storms from per-character streaming (esp. Ollama)
   → All providers share the same rAF gate
   → Final setAiExplanation runs after stream completes to flush last frame

4. Brief/Detailed position swapped (Brief is primary/left button)
   → Auto-trigger on text selection always uses 'simple' (Brief)
   → Manual Detailed click aborts in-flight Brief and starts new stream

5. Settings split: AI config in Settings page, typography in Reader panel
   → Design choice: typography is contextual to reading, AI is global config
   → User must open a book to adjust typography defaults
